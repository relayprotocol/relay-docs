With Relay, your app can make Solana-origin transactions gasless for your users: a sponsor wallet your app controls pays the transaction fees and rent, and your users need zero SOL. You request this with one quote parameter, **`depositFeePayer`**, and your app co-signs each transaction as the fee payer.

This is a different mechanism from [permit-based gasless swaps](/features/gasless-swaps), which rely on EVM token permits and do not exist on Solana. On Solana, gasless means your sponsor wallet pays, and this guide walks through the full flow.

In this guide, you learn how to:

- [Get a quote](#get-a-quote-with-a-sponsor) with your sponsor as the fee payer
- [Assemble the transaction](#assemble-the-transaction) from the returned instructions
- [Sign it safely](#sign-sponsor-first-then-user), sponsor first, then the user
- [Submit and track](#submit-and-track) the request to completion

## Before you start

- **A sponsor wallet funded with SOL**: It pays the transaction fees and any rent for account creation, so keep it topped up. Your backend holds its key; it never touches the client.
- **A Relay [API key](/references/api/api-keys)**: Your backend uses it for quotes.
- **`@solana/web3.js`** on your backend for transaction assembly and signing.

<Warning>
Three restrictions from [Solana Fee Sponsorship](/features/fee-sponsorship#solana-fee-sponsorship) apply to every step below. The **`depositFeePayer`** must be a different address from **`user`**, and the quote API does not reject a request where they match, so your app must enforce this. The sponsor must sign the transaction **before** the user, or the user could modify it to drain the sponsor. And do not use **`depositFeePayer`** for same-chain Solana swaps with untrusted users, as that combination is exploitable.
</Warning>

## Build the gasless flow

<Steps>
  <Step title="Get a quote with a sponsor" id="get-a-quote-with-a-sponsor">
    Request a quote as usual, and set **`depositFeePayer`** to your sponsor wallet. Relay then builds and sizes the transaction with the sponsor as the paying account, which matters because a user with no SOL would fail simulation otherwise.

    ```bash
    curl -X POST "https://api.relay.link/quote/v2" \
      -H "Content-Type: application/json" \
      -H "x-api-key: YOUR_API_KEY" \
      -d '{
        "user": "USER_SOLANA_ADDRESS",
        "recipient": "RECIPIENT_ADDRESS",
        "originChainId": 792703809,
        "originCurrency": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
        "destinationChainId": 8453,
        "destinationCurrency": "0x833589fcd6edb6e08f4c7c32d4f71b54bda02913",
        "tradeType": "EXACT_INPUT",
        "amount": "5000000",
        "depositFeePayer": "SPONSOR_SOLANA_ADDRESS"
      }'
    ```

    The response contains a `deposit` step whose item carries raw `instructions`, `addressLookupTableAddresses`, and a `check` endpoint for tracking. The user is the only signer inside the instructions; the sponsor becomes a signer in the next step, as the transaction's fee payer.
  </Step>
  <Step title="Assemble the transaction" id="assemble-the-transaction">
    On your backend, build a versioned transaction from the returned instructions, with the sponsor as **`payerKey`**. Instruction `data` is hex-encoded.

    ```typescript expandable
    import {
      AddressLookupTableAccount,
      Connection,
      PublicKey,
      TransactionInstruction,
      TransactionMessage,
      VersionedTransaction,
    } from "@solana/web3.js";

    const connection = new Connection(SOLANA_RPC_URL);
    const item = quote.steps[0].items[0];

    // 1. Rebuild the instructions returned by the quote
    const instructions = item.data.instructions.map(
      (i) =>
        new TransactionInstruction({
          programId: new PublicKey(i.programId),
          keys: i.keys.map((k) => ({
            pubkey: new PublicKey(k.pubkey),
            isSigner: k.isSigner,
            isWritable: k.isWritable,
          })),
          data: Buffer.from(i.data, "hex"),
        })
    );

    // 2. Resolve the address lookup tables
    const lookupTables = (
      await Promise.all(
        (item.data.addressLookupTableAddresses ?? []).map((address: string) =>
          connection
            .getAddressLookupTable(new PublicKey(address))
            .then((res) => res.value)
        )
      )
    ).filter((t): t is AddressLookupTableAccount => t !== null);

    // 3. Compile with the sponsor as the fee payer
    const message = new TransactionMessage({
      payerKey: new PublicKey(SPONSOR_SOLANA_ADDRESS),
      instructions,
      recentBlockhash: (await connection.getLatestBlockhash()).blockhash,
    }).compileToV0Message(lookupTables);

    const transaction = new VersionedTransaction(message);
    ```
  </Step>
  <Step title="Sign: sponsor first, then user" id="sign-sponsor-first-then-user">
    Sign with the sponsor key on your backend, then hand the partially signed transaction to the client for the user's signature. The sponsor key never leaves your backend, and the user key never leaves their wallet.

    ```typescript
    // Backend: the sponsor signs first
    transaction.sign([sponsorKeypair]);

    // Client: the user signs the partially signed transaction
    const signed = await userWallet.signTransaction(transaction);
    ```
  </Step>
  <Step title="Submit and track" id="submit-and-track">
    Broadcast the fully signed transaction, then poll the quote's `check` endpoint until the request reaches a terminal status.

    ```typescript
    const signature = await connection.sendRawTransaction(signed.serialize());

    // Poll until "success" or "failure"
    const status = await fetch(
      `https://api.relay.link${item.check.endpoint}`
    ).then((r) => r.json());
    ```

    A failed fill refunds automatically on the origin chain in the origin currency; see [Refunds](/references/api/api_core_concepts/refunds) for the conditions.
  </Step>
</Steps>

## What the sponsor does and doesn't pay

**`depositFeePayer`** covers the origin transaction only: Solana transaction fees and rent for accounts the deposit creates. It is independent from the destination side and from your [App Balance](/features/fee-sponsorship#funding-your-app-balance). To also sponsor destination gas or rent, use [`subsidizeFees` and `subsidizeRent`](/features/fee-sponsorship#sponsorship-parameters), which draw from your App Balance instead of the sponsor wallet.

Each trade is one Solana deposit transaction, so the sponsor pays one fee per trade. If you also want fills to start before the deposit confirms, see [Fast Fill](/features/fast-fill).
