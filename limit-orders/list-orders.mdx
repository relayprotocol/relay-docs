---
title: "List Orders"
description: "List your account's limit orders, or read one order by id."
openapi: get /orders
hidden: true
---

Orders come back newest first by default; pass `orderId` to read one order.

- An `orderId` that doesn't exist returns an empty `orders` array, not a `404`.
- `status` values are matched as given, so an unknown status returns an empty list rather than an error.
- `user` matches EVM addresses in any letter case.
- With `orderId`, the response also carries `status` and `txHashes`, the answer to the `authorize` step's `check`. `txHashes` is always empty because signing sends no transaction.

Step 4 of the [integration guide](/limit-orders/guide#webhooks) covers monitoring orders, including the `order.updated` webhook.
